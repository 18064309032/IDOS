# IDOS 接口调用链路

更新日期：2026-10-14。

本文按当前源码记录**运行时接口调用**，用于定位入口、状态归属和通知回路。它不是旧工程功能清单，也不把架构设计中的待实施接口当作现有实现。类型和签名以对应头文件为准；业务状态见[工作进度](工作进度-CJW.md)，职责边界见[架构设计](IDOS架构设计.md)。

## 1. 总入口与服务装配

```text
src/main.cpp::main
  → IDOSApplication（注册内置数据解析 Provider）
  → IDOSMainWindow::IDOSMainWindow
      → initProviders：注册 TreeMetadata / TreeGuiProvider / 默认树分组 / RenderMetadata
      → IDOSTreeServer::addTree(dataTree, caseTree)
      → createView → IDOSRenderServer::addView；IDOSToolBar::setRegistry
      → initDockWidgets：TreeView::setModel / setRegistry / setTargetView
      → IDOSSimulation::initialize → 装配模拟主页动作、窗口与工程监听
      → initPluginManager → IDOSPluginRegistry 加载插件 → IDOSPlugin::initGui
  → QApplication::exec
```

主窗口拥有本次运行的服务及两棵树。`IDOSAppInterface` 将 `project()`、数据/树/渲染/工具/命令 Registry、`renderServer()` 和主页 Panel 提供给插件；插件通过该接口注册具体能力。`IDOSPluginRegistry` 负责加载、调用 `initGui()` 和卸载；数值模拟由主窗口直接拥有和装配，不经过插件注册器。注册一个 Metadata 只建立创建入口，不等于项目里已经有对应数据，也不等于该业务按钮已实现。

新建工程：`IDOSMainWindow::createProject` 创建 `IDOSProject`，再调用 `setProject`；后者把同一工程绑定到 `IDOSRenderServer::setProject`、助手服务和 `IDOSTreeServer::setProject`。当前打开、保存、另存为、工程设置入口禁用；本链路不包含工程文件序列化。工程保存/重开是必要的后续功能，当前暂缓实施。

## 2. 改动数据的统一链路

```text
界面 / 插件 / 助手
  → project->commandManager()->execute(command)
    或 execute(commandName, JSON arguments)
  → IDOSCommandManager::execute
  → IDOSCommand::execute → validateCommand / apply
  → IDOSProject::add / take / remove，或具体数据对象修改
  → Project 的新增、变更、删除前、删除信号
      ├─ IDOSTreeServer：更新树节点与分支
      └─ IDOSRenderServer：更新各视图的渲染对象与依赖
  → CommandManager 保存成功 Action 的历史、result/error，发出状态信号
```

`execute(name, arguments)` 先通过 `IDOSCommandRegistry` 中的 `IDOSCommandMetadata::create` 构造命令，再走相同的 `execute(command)`。助手 `IDOSAssistantService` 绑定工程与注册表后也走名称入口。失败命令不进入历史；撤销/重做由 Manager 调用命令反向/再次执行。`Project::beginUpdate/endUpdate` 合并通知，不代替失败回滚。

数据对象的稳定 ID 是命令和引用的目标。树节点 ID、数据 ID、渲染对象 ID 不可混用。菜单在打开时保存目标数据 ID 和目标视图；执行时重新查询并校验，不能仅凭后来变化的“当前对象”猜目标。

## 3. 文件导入

```text
树菜单 / 工况入口 / 助手
  → IDOSImportObjectsCommand（src/app/command/idosimportcommands.cpp）
  → IDOSDataProviderRegistry::providers(filePath)
  → IDOSDataProviderMetadata::create
  → IDOSDataProvider::read(filePath)
  → 命令校验、合并井或关联工况/网格/属性、提交到 Project
  → TreeServer / RenderServer 响应 Project 通知
```

具体命令元数据包括工况、网格、属性和井数据导入。Provider 只解析文件，返回数据对象；不直接修改工程、树或场景。命令负责目标归属、替换和撤销所需的状态。`simulation.results.import` 使用独立的 `IDOSImportRestartResultsCommand`，也经同一个 Manager 进入工程通知链路。

## 4. 工程通知到树

```text
IDOSProject::objectAdded / objectDataChanged / objectAboutToBeRemoved / objectRemoved
  → IDOSTreeServer 对应槽
  → IDOSTreeRegistry::metadata(typeId)
  → 具体 IDOSTreeMetadata::create → IDOSTreeProvider::populate/update
  → IDOSTree::insert/remove/节点变化
  → IDOSTreeModel 的 Qt 行与 dataChanged 信号
  → 数据树、工况树显示
```

`IDOSTreeServer` 只处理同步，不判断网格、井或工况的具体节点形状。各业务 `TreeProvider` 决定分组、子节点及引用。`IDOSTreeView::createMenu` 针对实际节点遍历适用 `TreeGuiProvider::populateMenu`；工况树单独允许空白菜单。右键先将目标节点置为当前节点，主窗口再同步当前对象/当前工况。

树勾选另有一条**局部显示**链路：

```text
IDOSTreeModel::setData(CheckStateRole)
  → checkRequested（DirectConnection）
  → IDOSTreeView::onCheckRequested
  → 唯一负责的 TreeGuiProvider::setChecked(item, checked, targetView)
  → 目标 View 的 RenderObject / 具体 RenderProvider
  → Scene::notifyChanged → View 刷新
  → GuiProvider::checkStateChanged → TreeView::refreshCheckStates
  → GuiProvider::isChecked 从目标视图实际状态读回勾选
```

`TreeModel` 不实现网格属性互斥或筛选条件。`TreeGuiProvider` 的复选框操作通常是视图局部状态，不经业务命令历史。场景变化时主窗口也刷新两棵树的视图勾选。默认对象是否可见与某个视图里是否显示，是不同状态。

## 5. 工程通知到渲染

```text
IDOSProject 通知 / RenderMetadata 注册变化
  → IDOSRenderServer::update / reload
  → IDOSRenderRegistry::metadata(typeId)
  → IDOSRenderMetadata::create(data)
  → IDOSRenderObject 接管 RenderProvider
  → RenderServer::bindDataReferences(provider)
  → RenderObject::update → View::scene()->add / notifyChanged
  → IDOSRenderView 重建 actor、图例并绘制
```

每个 `IDOSRenderView` 拥有独立 `IDOSRenderScene`；每个 Scene 拥有自己的 RenderObject 和 Provider。RenderServer 用 `dependencyIds()/setDataReference()` 绑定非拥有的数据依赖；属性等依赖变化时调用 `dependsOn()` 找到受影响 Provider。删除前先移除源对象，并通过 `removeDataReference()` 清理其他 Provider 的引用。View 关闭时 RenderServer 移除该视图及场景对象。

当前视图由 `IDOSRenderServer::currentView()/setCurrentView()` 管理。主窗口收到 `currentViewChanged` 后为数据树、工况树设置 `targetView`，并恢复该视图的当前对象/工况上下文。菜单打开后固定目标视图，不随用户后来切换活动视图而改变。

## 6. 网格、筛选与井的局部接口

| 操作 | 调用链 | 状态归属 |
|---|---|---|
| 网格/属性勾选 | `TreeModel → TreeView → IDOSGridTreeGuiProvider::setChecked → GridRenderProvider/RenderObject → Scene::notifyChanged` | 目标视图 |
| 网格显示设置 | `GridTreeGuiProvider 菜单 → IDOSGridSettingWidget::setProject/setView/setGrid/setPropertyId → onApply → GridRenderProvider → Scene` | 目标视图，不进命令历史 |
| 临时筛选 | `GridTreeGuiProvider 菜单 → IDOSGridFilterWidget::setProject/setView/setGrid/setFilter → onApply → GridRenderProvider::setFilterCriteria/update → Scene` | 目标视图的临时预览 |
| 保存筛选 | `GridFilterWidget::saveFilter → IDOSGridFilterCommand(create/update) → Project → 两个 Server` | `IDOSGridFilter` 数据对象及命令历史 |
| 筛选结果勾选 | `TreeModel → GridTreeGuiProvider::setChecked → 结果 RenderObject + 主网格 Provider 条件 → Scene` | 目标视图；取消时清理关联预览 |
| 井勾选/显示设置 | `TreeModel/菜单 → IDOSWellTreeGuiProvider → WellRenderProvider`；设置页由 `IDOSWellDisplayWidget` 更新目标 Provider 与 Scene | 目标视图 |
| 井导入/删除 | `WellTreeGuiProvider → Import/Create/Delete 命令 → Project → 两个 Server` | 工程数据及命令历史 |

`IDOSGridFilter` 保存筛选条件和源网格 ID，不复制完整网格几何。已保存结果的渲染 Provider 仍关联源网格及属性。工具条“隐藏全部/显示全部”由视图保存并恢复各 RenderObject 原有可见状态，不改动筛选条件或工程数据。

## 7. 数值模拟、动态结果与播放

```text
工况树选择/右键 → Project::setCurrentCaseId
  → 平台模拟动作取得当前工况
  → 预检 / 初始化 / IDOSSimulationRunStatusWidget
  → onStartTriggered：验证工况、网格引用和运行目录 → QProcess 启动 WSL2 Flow
  → onOutputReady：输出转发至主界面日志
  → onFinished：重新验证工程/工况/网格 → importResults
  → CommandManager::execute("simulation.results.import", gridId + UNRST 路径)
  → Project 新增/更新动态属性 → TreeServer / RenderServer
  → 结果播放控件变更属性报告步 → 数据变化通知 → Provider 更新与 Scene 刷新
```

Flow 是进程调用，不是 Project 命令；导入计算结果才进入命令历史。运行窗口关闭仅隐藏，停止任务走进程控制。结果播放按明确当前工况和网格引用定位目标，不能取工程里第一个同网格工况。当前真实计算验收主要覆盖 SPE1；其他工况和报告步组合需继续验收。

## 8. 工具、插件与助手的入口边界

- 视图创建时 `IDOSMainWindow::createView → IDOSRenderServer::addView → IDOSToolBar::setRegistry`。主窗口通过 `IDOSToolRegistry` 注册平台具体工具 Metadata，工具条创建动作；一次性动作调用目标 View/Provider，持续工具通过 `View::enableTool` 进入 Qt 输入过滤器和必要的 VTK 状态监听。工具局部操作不写工程历史。
- 插件通过 `IDOSInterface` 注册数据、树、渲染、工具和命令入口，并在共享主页 Panel 添加自己的动作；插件卸载时移除自有 UI 与注册项。应用负责服务所有权及工程切换，不让通用 core/gui/render 识别某个具体插件。
- `IDOSAssistantWidget → IDOSAssistantService → CommandManager::execute(name, arguments)` 是助手修改工程的路径；查询不进入历史。Python 控制台目前只有界面，不能列为已接通的命令调用方。

## 9. 排查时先确认的边界

1. **数据有没有改变**：先看命令结果和 Project 对象/通知，再看树与渲染同步；只刷新界面不能补救未提交的数据。
2. **仅显示不对**：先确定实际 `targetView`、数据 ID 与 RenderObject ID，再查 GuiProvider、Provider 状态和 `Scene::notifyChanged`；不要直接改 Project 的全局显隐去补一个局部视图问题。
3. **树勾选反跳**：确认 `GuiProvider::setChecked` 的写入和 `isChecked` 的读回是否针对同一视图及同一 RenderObject；工具条等旁路显示动作也必须触发状态刷新。
4. **导入后缺节点或画面**：按 Provider 解析结果 → 命令提交 → Project 通知 → Metadata 注册 → TreeServer/RenderServer 分段检查。
5. **插件功能看似有入口却不可用**：区分注册/菜单可见、实际命令或算法实现，以及真实数据验收；不能把占位 Action 当作已接通链路。

源码已按 2026-10-14 确认方案归类，完整文件树见 [源码目录](IDOS源码目录.md)。Provider/Metadata/Registry 通用接口集中于 core/providers，具体展示实现位于 app/providers，具体命令位于 app/command。gui 按业务目录组织界面文件，其中业务窗口由 app/CMakeLists.txt 显式列入 idos_app；通用 idos_gui 保持独立，物理目录不代表链接依赖。

对象交互：TreeView 菜单/Ctrl+C/X/V/拖放 → CaseTreeGuiProvider 校验工程会话、完整对象和实际目标 → objects.copy/move → CommandManager → TransferObjectsCommand 创建独立副本或改变归属 → Project 通知 → TreeServer/RenderServer 更新。重命名共用 object.rename。数据树“添加到工况…”单独调用 CaseReferenceCommand 建立已有数据关联；case.fluidRock.attach 继续共用关联实现。工况复制包含关联数据及网格、属性、筛选，并重映射 ID。


工程文件：MainWindow 打开/保存/另存为 → IDOSProject::load/save → DataRegistry 按 typeId 查找 DataMetadata → 具体对象 projectData/restoreProjectData → HDF5 原生数据集。加载先恢复原 ID 和全部对象，再由对象校验关系；成功后 MainWindow 切换工程，TreeServer/RenderServer 重建展示。保存先关闭临时 HDF5 文件，再由 QSaveFile 原子替换目的文件。旧源文件只作为来源信息，不参与数据恢复。


### 工程 UI 状态保存与恢复

保存：MainWindow 收集 TreeView、RenderServer 及测井曲线窗口快照 → IDOSProject::setPresentationState → IDOSProject::save 写入可选 presentation 字段。RenderServer 调用 View 和具体 Provider 的状态接口；数字与字符串沿用紧凑 HDF5 编码。

打开：Project 独立加载并校验业务数据 → MainWindow 清理旧视图、重建保存的视图集合 → TreeServer/RenderServer 装入工程 → RenderServer 通过数据 ID 恢复 Provider、绑定依赖、更新展示、恢复相机与联动 → MainWindow 恢复树选择与展开。恢复期间不标记修改；正常交互标记工程需要保存。本机窗口几何、ADS 布局和最近工程单独写 QSettings。
