更新日期：2026-10-12

本文记录当前工程已落地的主要能力、尚未完成的工作和后续顺序。状态按当前源码核对；“已实现”表示代码中已有对应功能，不代表所有功能都已完成完整的端到端验收。

## 当前进度

### 平台与框架

- 工程、数据对象、工况、树视图、渲染视图、命令撤销重做和插件管理等平台基础功能已形成。
- 平台提供工程数据导入和新建工况流程。数值模拟插件不再重复实现 DATA 导入和新建工况入口。
- 网格动态属性可存储多个报告步，并可通过 UNRST 导入命令进入工程。
- 插件可扩展树节点和对象交互；插件存在仍被工程或命令历史引用的数据时，会拒绝卸载。

## 当前数值模拟流程

```text
平台导入 DATA / 新建工况
          ↓
运行预检
          ↓
初始化运行目录并复制输入文件
          ↓
当前软件尚未启动模拟器
          ↓
如运行目录中已有 UNRST，可手动导入为动态属性并播放报告步
```

OPM 已用于 Eclipse 输入和结果文件解析；这不等于软件已经集成 OPM Flow 等求解器。当前代码中没有模拟器进程启动实现。

## 下一阶段：接通模拟器运行与结果闭环

1. 确认要调用的模拟器可执行程序及其启动参数，并确定配置保存位置。
2. 从已初始化的运行目录启动模拟器，记录运行中、成功、失败和退出码等状态。
3. 将进程标准输出和错误输出显示在运行状态/输出界面。
4. 模拟器成功结束后检查输出文件，定位 UNRST 并通过现有导入命令自动导入当前工况网格。
5. 对缺少 UNRST、解析失败、网格不匹配和重复属性等情况显示明确结果，不把失败标记为运行成功。
6. 完成一次真实算例的端到端验收：预检 → 初始化 → 启动 → 完成 → 自动导入 → 报告步播放。
