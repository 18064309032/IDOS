## 准备

阅读 [AGENTS.md](../AGENTS.md)、[架构设计](IDOS架构设计.md)、[源码目录](IDOS源码目录.md)、[接口调用链路](接口调用链路.md)和[工作进度](工作进度-CJW.md)。固定目录决定类归属，功能状态以进度摘要为准；历史记录不代表当前仍保留旧接口。

当前使用 Windows x64、MSVC、Qt 5.15.2、C++17。预设采用 version 4，建议 CMake 3.23 或更高；根脚本声明 3.16，但实际还使用更高版本命令，不承诺旧版本完整兼容。

## 构建

构建目录统一为源码根目录上一级的 `IDOS-Build`（`${sourceDir}/../IDOS-Build`），不绑定任何机器的绝对路径。从仓库根目录运行：

```powershell
cmake -S . -B ../IDOS-Build `
    -G "Visual Studio 17 2022" -A x64 `
    -DIDOS_QT_DIR="D:/Qt/Qt5.15.2/5.15.2/msvc2019_64" `
    -DIDOS_BUILD_TESTS=ON -DIDOS_ENABLE_RENDER=ON
cmake --build ../IDOS-Build --config Debug --parallel 6
```

本地预设可参考 `CMakeUserPresets.example.json`，优先使用 `cmake --preset win-x64-debug-local` 和 `cmake --build --preset debug`，由继承的预设确定相对源码的构建目录。禁止源码内构建；运行和验证均使用该目录的最新产物。

程序和平台 DLL 在 `bin/Debug/`，插件在其 `plugins/`，翻译在 `i18n/`，模型资源在 `resources/assistant/`，OPM 自定义关键字在 `resources/opm/`。Debug 为 `idosd.exe`，Release 为 `idos.exe`；Release 也在同一构建目录用 `--config Release` 构建，最近验收记录针对 Debug。

运行进程占用 DLL 时先关闭对应程序再替换。构建不提供 WSL 或 Flow 安装环境。`IDOS_ENABLE_RENDER=OFF` 目前不是已验证的独立无渲染模式。

## 验证

```powershell
cmake --build ../IDOS-Build --config Debug `
    --target idos_render_header_checks check_includes --parallel 6
ctest --test-dir ../IDOS-Build -C Debug --output-on-failure
git diff --check
```

| 测试 | 覆盖 |
|---|---|
| check_includes / check_includes_regressions | 模块边界、公共头归属及检查器回归 |
| command_registry | 命令注册、验证、执行与历史 |
| assistant_widget | 助手请求、命令及工程切换 |
| project_dialog | 工程对话框与主窗口 |

变更目标重新编译后再测试，避免旧二进制造成误判。按风险选择验证；文档修改检查链接和事实，不需要重复完整构建。

实际 Flow 用例由 `IDOS_FLOW_SMOKE_DATA` 启用，指向准备好的 SPE1 DATA 及完整 INCLUDE 包。未设置时对应用例跳过；普通测试不能隐式依赖个人环境或外网。

## 翻译与资源

源文本使用英文 `tr()`，中文写入 TS，不翻译内部标识、协议字段和文件路径。

```powershell
cmake --build ../IDOS-Build --config Debug --target lupdate
cmake --build ../IDOS-Build --config Debug --target translations
```

数值模拟、井显示及内置视图工具翻译合并到 `i18n/idos_zh_CN.ts`；其他插件使用独立 TS，由各插件 CMake 管理编译和部署。平台 lupdate 不代表插件翻译已更新；部署最新 QM 后验证中文。

`resources/assistant/local-ai.json` 定义相对于助手目录的 runtime、model 和启动参数，当前配置为 Vulkan 后端。更换模型或后端需核对实际资源；CMake 当前部署固定模型文件，资源缺失可能导致部署失败。

Flow 与 opm-common 是独立依赖，前者通过 WSL 运行，后者用于解析；流程见 [使用指南](使用指南.md)。

## 扩展与贡献

具体数据及 DataMetadata 放在 core/data 的业务目录，具体格式解析放在 providers 的业务目录；具体展示及菜单实现放在 app/providers，命令放在 app/command，内置工具放在 app/providers/render，专业扩展放在插件。通用接口按源码目录文档归入所属模块根部或 providers 子目录，不增加未确认目录或类。插件只使用公共入口，不链接 App 内部实现。参见 [插件开发](../src/plugins/README.md)。

视图工具覆盖 `IDOSTool::onEventFilter()` 处理 Qt 输入，使用 `observeVtkEvent()` 的 VTK 成员函数监听，覆盖 `onVtkEvent()` 处理状态。不使用友元、手写静态回调、SLOT 连接或额外事件分发框架。

提交说明问题、最终行为和实际验证，同步翻译与工作进度。不要将局部回归描述为全量验收，不以关闭新警告替代根因处理。完整代码规范以 AGENTS.md 为准。

源码已按 2026-10-14 确认方案归类，完整文件树见 [源码目录](IDOS源码目录.md)。Provider/Metadata/Registry 通用接口集中于 core/providers，具体展示实现位于 app/providers，具体命令位于 app/command。gui 按业务目录组织界面文件，其中业务窗口由 app/CMakeLists.txt 显式列入 idos_app；通用 idos_gui 保持独立，物理目录不代表链接依赖。


## PROJ 依赖与工程坐标（2026-10-20）

PROJ 9.9.0 依赖已按第三方 include/lib/bin 方式接入，core 私有链接 PROJ::proj。源码来源和重建说明见 thirdparty/proj/README.md。工程不附带第三方源码压缩包；tools/BuildProj.ps1 按需下载至源码兄弟 IDOS-Build/thirdparty-proj/downloads，校验 SHA256 后重建两种配置，缓存齐备后可离线重建，要求 VS2022 x64 C++ 工具及 CMake 3.22.1 以上；依赖和数据库生成器在源码兄弟 IDOS-Build/thirdparty-proj 构建，不在源码目录生成缓存。主工程配置仍用原有 CMake preset。

运行时必须部署匹配配置的 PROJ DLL 和 resources/proj/proj.db；默认禁网，压缩 TIFF 格网支持已编译，所需区域格网可随资源增加。IDOS 不使用环境变量猜测数据库路径，不静默接受 ballpark 或缺少最佳格网的替代操作。

coordinates.transform 查询参数为 sourceCrs、targetCrs、扁平 XYZ 数组 xyz，以及动态参考框架所需的 decimalYear。经纬度顺序为经度、纬度，单位统一为度；投影/地心坐标单位按 CRS 定义，查询不会改变工程数据。工程局部坐标换算使用 IDOSProjectMetadata::transformCoordinates，其源/目标均需明确坐标类型和 Z 方向，局部原点为米制，旋转为从参考 X 轴向局部 X 轴逆时针。设置修改命令 project.settings.update 接收完整 metadata 对象并可撤销。

## AI 助手进程退出清理（2026-10-20）

Windows 下 IDOSLocalModelProcess 为每次模型启动创建独立、不可继承句柄的 Job，启用 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE。通过 QProcess 的 Windows 创建参数接口及 PROC_THREAD_ATTRIBUTE_JOB_LIST，在创建进程时完成归组，避免进程先运行再绑定的时间空隙。此方式要求 Windows 10 / Windows Server 2016 或以上；配置失败即拒绝启动，不降级为无保护运行。

正常停止仍先请求模型退出，超时后强制结束，再关闭 Job 清理残留后代；启动失败、重复启停和析构均释放句柄。VS 停止调试、主程序崩溃或被强制终止时，由系统回收最后一个 Job 句柄并结束组内模型及后代进程。仅管理本实例启动的进程，不查杀同名外部服务；更新前遗留的进程不属于新 Job。

idos_assistant_widget_tests 的 onProcessLifetime 使用轻量测试进程代替模型，覆盖正常退出、强制终止及 fail-fast 异常退出，并分别等待子进程、孙进程句柄结束；onProcessRestartAfterFailure 覆盖无效可执行文件启动失败和后续两次启停。不加载真实模型，不消耗模型显存。
